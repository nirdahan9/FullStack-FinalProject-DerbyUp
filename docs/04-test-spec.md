## 1. אסטרטגיית הבדיקות

### 1.1 מה בודקים ומה לא

ההנחיות קובעות: *"לא חובה לבדוק כל שורת קוד, אבל חובה לבדוק את התהליכים המרכזיים."*

| נבדק בקפדנות | נבדק בסיסית | לא נבדק |
|---|---|---|
| לוגיקת ניקוד ויישוב | קומפוננטות UI מרכזיות | קומפוננטות shadcn/ui |
| הרשאות ובידוד נתונים | טפסים | סגנון ופריסה |
| ולידציות קלט | ניווט | לוגים |
| התהליך העסקי מקצה לקצה | | קוד ספריות צד ג' |

### 1.2 פירמידת הבדיקות

```
        ╱╲          E2E — Playwright
       ╱  ╲         מעט, איטיות, מכסות את המסע המלא
      ╱────╲
     ╱      ╲       אינטגרציה — Vitest מול Supabase
    ╱        ╲      בעיקר RLS והרשאות
   ╱──────────╲
  ╱            ╲    יחידה — Vitest
 ╱______________╲   רבות, מהירות, על lib/domain/
```

**הרוב המכריע של הלוגיקה העסקית נבדק ביחידה**, כי `lib/domain/` תוכננה כפונקציות טהורות
בלי I/O — אפשר לבדוק אותה בלי DB, בלי רשת ובלי mock.

### 1.3 כלים

| כלי | שכבה |
|---|---|
| **Vitest** | יחידה + אינטגרציה |
| **React Testing Library** | קומפוננטות |
| **Playwright** | E2E בדפדפן אמיתי |
| בדיקות ידניות מתועדות | מה שלא כדאי לאוטמט (§9) |

## 10. יעדי כיסוי

| אזור | יעד | נימוק |
|---|---|---|
| `lib/domain/` | **90%+** | לב הלוגיקה העסקית; טהור ולכן קל לכיסוי |
| `lib/validation/` | **90%+** | קריטי לאבטחה |
| `lib/actions/` | 60%+ | נבדק בעיקר באינטגרציה |
| קומפוננטות | 40%+ | המרכזיות בלבד |
| **הרשאות ו-RLS** | **100% מהתרחישים ב-§5** | אין פשרה |

> הכיסוי אינו מטרה בפני עצמו. **תרחיש שלא נבדק חשוב יותר מאחוז חסר.**
