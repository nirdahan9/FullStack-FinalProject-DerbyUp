## 🎯 מה נשאר — לפי בעלים

### אצלי (קוד ותיעוד)

ביקורת ב-22.8 עברה על כל Server Action, כל הישג וכל סוג התראה — לא "האם זה
נכון" אלא **"האם מישהו קורא לזה"**. ארבעה פערים נמצאו ותוקנו, והקוד הוכרז סגור.

> ### 🔄 נפתח מחדש ב-22.8 בערב — **תוצאות חיות** (שלב 14)
>
> ניר ביקש לפורט את פיצ'ר הלייב מהפרויקט המקורי. נבנה במלואו באותו ערב:
> מיגרציה, קרון שלישי, שכבת תחזית טהורה, UI, **49 בדיקות חדשות** ועדכון של
> ששת מסמכי ההגשה.
>
> **מה שהחליט את היקף העבודה:** הפיצ'ר **לא הוסיף טבלה ולא שינה את
> `league_standings`**, כי הדירוג כבר היה מחושב ולא מאוחסן. השכבה החיה היא עוד
> מקור נתונים לאותו חישוב.
>
> **מה שנשאר לניר:** להריץ `npm run schedule:cron` אחרי הדיפלוי הבא — ה-job
> החדש קורא ל-endpoint שעדיין לא קיים בפרודקשן.

> ### 🔄 נפתח שוב ב-22.8 בלילה — **דף נחיתה** (שלב 15)
>
> הדף הקודם היה כרטיס אחד ושני כפתורים, ולא הסביר מה המוצר עושה. נבנה מחדש
> כשער כניסה מלא: הירו עם שלושה **משחקים אמיתיים** ומחיריהם, שלושת הצעדים,
> מודל הניקוד עם הבונוס ×3, רשת הפיצ'רים, ו-FAQ שפותח ב"רגע — זה הימור?".
>
> **מה שהחליט את היקף העבודה:** אורח אינו `authenticated`, ולכן שלוש הטבלאות
> שהדף צריך היו סגורות בפניו. במקום להרפות שלוש policies נפתחה פונקציה אחת
> צרה — אותה תבנית של הלידרבורד הכללי. זו **הפונקציה היחידה במוצר שמוענקת
> ל-`anon`**, והיא מחזירה נתונים פומביים בלבד: שמות קבוצות, מועד ומחיר.
>
> **מה שנשאר לניר:** כלום. המיגרציה כבר הורצה מול הפרויקט (`db-exec`), ואומתה
> מול מפתח ה-anon — הפונקציה מחזירה שלוש שורות, וחמש הטבלאות עדיין מחזירות
> ריק.

```
   ├── Next.js 16 App Router ── Vercel
   │     ├─ Server Components  → קריאת נתונים ישירה מהשרת
   │     ├─ Server Actions     → כתיבה: הימור, ליגה, הצטרפות, אתגר יומי
   │     └─ Route Handlers     → /api/cron/* בלבד
   │
   ├── Supabase Auth           → אימייל+סיסמה, session ב-cookies
   ├── Supabase Postgres + RLS → מקור אמת יחיד
   └── Vercel Cron             → סנכרון משחקים · עיבוד הימורים · פרסום אתגר יומי
             │
             └── API-Football (v3.football.api-sports.io)
```

### החלטות שצריך לדעת להסביר בהצגה

| החלטה | נימוק |
|---|---|
| App Router + Server Components | טעינה בשרת = פחות JS ללקוח, פחות round-trips — נכנס ישירות למסמך הסקייל |
| Server Actions במקום REST | פחות boilerplate, type-safety מקצה לקצה, ולידציה בשרת בלבד |
| RLS כשכבת ההרשאות הראשית | ההנחיות שואלות "איך אתם מונעים גישה למידע של משתמש אחר" — זו התשובה החזקה ביותר |
| ledger (`point_transactions`) | היתרה נגזרת מתנועות ולא מעודכנת ישירות — מונע race conditions ונותן audit trail |

> ⚠️ **בוטל.** אין יתרה ואין הימור, ולכן אין מה לנהל בספר תנועות. הנקודות רק
> נצברות, וכל צבירה מתועדת בטבלה שגרמה לה (`predictions` · `puzzle_attempts`).
> דירוג הליגה **מחושב** מהניחושים ולא נשמר, כך שהוא לא יכול לסטות מהם.
| Zod | סכימה אחת משותפת client+server |
| API-Football בלבד | ספק אחד לכל הנתונים: משחקים, תוצאות **ו-odds**. פחות תלויות, פחות סודות |
| autocomplete מקומי | רשימת שחקנים ב-DB, לא קריאת API בכל הקלדה |

אם נופלים מאחור, מקצצים **בסדר הזה** — מהנמוך לגבוה בערך הרובריקה:

| # | מה מקצצים | חוסך | למה זה ראשון |
|---|---|---|---|
| 1 | Football Bridge | 2.0 | לולאת מוצר נפרדת; לא מוסיף שום סעיף ברובריקה |

| 3 | אופציית tournament | 0.5 | ליגת pool לבדה מספיקה להדגמה |
| 4 | Featured game | 0.5 | נחמד לאדמין, לא קריטי |
| 5 | התראות | 1.0 | מדגים RLS — אבל RLS כבר מודגם במקומות אחרים |

**מה שאסור לקצץ בשום מצב:** שלושת מסמכי התכנון · RLS ובדיקותיו · מסמך אפיון הבדיקות ·

## 7. אינטגרציית API-Football

> ⚠️ **המכסה השתנתה:** המסלול בפועל הוא **Ultra — 75,000 קריאות ליום** ולא
> 100. הניצול בפועל הוא 0.27%. ראה [05-scale.md](../05-scale.md) §10.5.

**ספק יחיד לכל הנתונים.** Base: `https://v3.football.api-sports.io` · Header: `x-apisports-key`

| תחרות | league id |
|---|---|
| ליגת העל (ישראל) | 383 |
| Premier League (אנגליה) | 39 |
| La Liga (ספרד) | 140 |
| Serie A (איטליה) | 135 |
| Bundesliga (גרמניה) | 78 |
| Ligue 1 (צרפת) | 61 |
| Champions League | 2 |

**Endpoints:** `/fixtures` (משחקים ותוצאות) · `/odds` (יחסים)

**מקורות לפורט מהפרויקט הקיים:**
- `backend/src/services/footballApi.js:160-234` — פרסור `/odds`. כבר מחזיר **בדיוק** את שלושת
  השווקים שבחרנו: `home/draw/away`, `over_2_5/under_2_5`, `btts_yes/btts_no`
- `backend/src/services/sportsApi.js` — `buildBetQuestions()`, לוגיקת בניית השאלות

> ⚠️ **מכסה:** ה-tier החינמי מוגבל ל-**100 קריאות ביום**. 7 תחרויות × fixtures + odds יכול
> לחרוג. מענה: cron אחד ליום שמושך fixtures לשבוע קדימה, odds רק למשחקים שנבחרו לליגות
> פעילות, ו-cache ב-DB. זו נקודה טובה למסמך הסקייל.

> ✅ **The Odds API כבר לא נדרש** — API-Football מספק את היחסים. ספק אחד במקום שניים.
